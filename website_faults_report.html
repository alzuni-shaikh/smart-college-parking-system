🔍 Manual Website Testing & Highlighted Faults Report

System: Smart College Parking System (SOCMAC Smart Park) | Note: Issues highlighted only, not resolved per instructions

1. Production Live Site Blank White Screen (Asset Path 404s)
Critical Severity
The live production website deployed via GitHub Pages at https://alzuni-shaikh.github.io/smart-college-parking-system/ renders as a completely blank white page. In frontend/vite.config.js, base: '/' was hardcoded for Vercel. As a result, HTML requests /assets/index-BLr4mFsi.js at domain root instead of the GitHub Pages repository subpath, returning HTTP 404 Not Found for all bundle JS/CSS files.
// In frontend/vite.config.js: export default defineConfig({ plugins: [react()], base: '/', // ❌ BUG: Causes 404 on https://alzuni-shaikh.github.io/smart-college-parking-system/ ...
Impact: End users visiting the live URL see a 100% blank page and cannot load the application.
2. Uncaught ReferenceError: 'currentUid' is not defined in App.jsx
Critical Severity
In frontend/src/App.jsx line 1735 inside the payment confirmation handler, recordSuccessfulPayment references currentUid which is never declared or passed into that scope (the user object is named user?.uid or userProfile?.uid).
// In frontend/src/App.jsx line 1733: recordSuccessfulPayment({ paymentId: `PAY-${slotId.replace(/[^a-zA-Z0-9]/g, '')}-${nowTimestamp}`, userId: currentUid, // ❌ BUG: 'currentUid' is not defined (Throws ReferenceError) studentName: ownerName || 'Campus Member', ...
Impact: Attempting to record successful payments crashes with an unhandled JavaScript runtime error.
3. Missing "Student Demo" and "Admin Demo" Buttons (Documentation Contradiction)
High Severity
The official project README.md explicitly advertises: "1-Click Demo Access: Instant Student Demo and Admin Demo buttons to explore all features immediately without requiring external credentials." However, inspecting frontend/src/pages/Login.jsx reveals that NO demo buttons exist in the component. Unauthenticated users without a live Google/Firebase credential cannot bypass the login screen without manually hacking localStorage in DevTools.
Impact: Evaluators and testers cannot access the application features advertised in the documentation.

High Severity
Running npm run lint in the frontend reveals 55 errors. Core components like Navbar.jsx, ParkingLotMap.jsx, and WrongParkingReportModal.jsx call setState synchronously inside useEffect bodies, triggering cascading renders, potential infinite render loops, and race conditions.
// In Navbar.jsx, ParkingLotMap.jsx, WrongParkingReportModal.jsx: useEffect(() => { if (!currentUid) { setNotifications([]) // ❌ Avoid calling setState() directly within an effect return ...
Impact: Sub-optimal rendering performance, unneeded component re-mounts, and CI lint failure.
5. Missing .env File & Mock Firebase Credentials Fallback
Medium Severity
No .env or .env.example exists in the frontend. When built without environment variables, firebase.js falls back to dummy strings (apiKey: 'mock-api-key', projectId: 'mock-app'). Submitting standard email login produces authentication failures without helpful guidance.
Impact: Fresh checkouts require undocumented environment setup to operate live Firebase features.
6. Monolithic 1.54 MB Unsplit JavaScript Bundle
Medium Severity
The production build generates a single chunk dist/assets/index-BLr4mFsi.js of 1.54 MB (exceeding Vite's 500 kB limit). Admin views, student views, scanner engines, and icon libraries are bundled into the initial entry point without dynamic React.lazy imports.
Impact: Slower initial page load times and higher mobile data consumption for students on campus networks.
7. NPM Dependencies Security Audit Vulnerabilities
Medium Severity
Dependency scanning reveals 3 vulnerabilities in backend (1 moderate, 1 high, 1 critical) and 16 vulnerabilities in frontend (6 moderate, 10 high) in transitive packages (vite, rollup, express).
Impact: Potential security risks in production deployment if dependencies are not updated.
